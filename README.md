# AI Frame

A lightweight framework for managing Claude Code sessions across projects. It reduces context window usage and token costs by persisting project knowledge locally, and uses a generated master system prompt to enforce consistent coding standards across all sessions.

---

## The Problem

Every new Claude Code session starts blank. You repeat yourself — re-explaining architecture, conventions, current state, and recent decisions — burning tokens and wasting time. Over many sessions this compounds significantly.

## The Solution

AI Frame does three things:

1. **Generates a `CLAUDE.md`** master system prompt tailored to your project by asking you a series of targeted questions during initialisation. Claude Code automatically reads this file in every session.

2. **Maintains local context files** (`.ai-frame/`) that capture architecture notes, decisions, and session summaries. These are small, human-readable markdown files you curate over time.

3. **Provides session scripts** that let you start a session with a pre-built briefing, and end a session by recording what was accomplished, updating progress state, and logging decisions.

## File Structure

```
ai-frame/                    ← This repository
├── init_project.py          ← Run once per project to initialise
├── session_manager.py       ← Run at start and end of every session
├── context_builder.py       ← Build a compressed context snapshot
└── README.md

your-project/                ← Your actual coding project
├── CLAUDE.md                ← Generated master system prompt (auto-read by Claude Code)
└── .ai-frame/
    ├── config.json          ← Project metadata (auto-generated, rarely edited)
    ├── progress.md          ← Current status, in-progress work, next tasks
    ← EDIT THIS REGULARLY →
    ├── architecture.md      ← System design, components, data flow
    ← EDIT WHEN DESIGN CHANGES →
    ├── decisions.md         ← Log of architectural and design decisions
    ← APPEND WHEN DECISIONS ARE MADE →
    └── sessions/
        ├── 2025-01-15.md    ← Session summary (auto-generated by session_manager)
        └── 2025-01-16.md
```

## Quick Start

### 1. Clone or download AI Frame

```bash
git clone https://github.com/yourname/ai-frame.git
# or just download the three .py files anywhere convenient
```

### 2. Initialise your project

Navigate to your project directory (or use `--project-dir`) and run the wizard:

```bash
cd your-project
python /path/to/ai-frame/init_project.py
```

The wizard asks about your project type, language, architecture, testing strategy, coding standards, constraints, and more. It then generates:

- `CLAUDE.md` — the master system prompt Claude Code loads automatically
- `.ai-frame/config.json` — project metadata
- `.ai-frame/progress.md` — empty progress tracker to fill in
- `.ai-frame/architecture.md` — empty architecture doc to fill in
- `.ai-frame/decisions.md` — decision log with one initial entry

**Immediately after initialisation**, open the generated files and fill in the blanks in `architecture.md` and `progress.md`. The more you put in now, the more useful Claude becomes.

### 3. Start a session

```bash
python /path/to/ai-frame/session_manager.py start --project-dir your-project
```

This prints a formatted briefing of current progress, recent sessions, and project config. Use this output as the **first message** in your Claude Code session — or just let Claude Code read it from `CLAUDE.md` and the `.ai-frame/` files directly (no paste needed if you instruct Claude to read those files).

### 4. Work with Claude Code

Open `your-project/` in Claude Code. Because `CLAUDE.md` lives in the root, Claude Code loads it automatically. Claude will:

- Know your project's architecture, language, and conventions
- Follow your testing strategy and style guide
- Respect your hard constraints and avoid listed anti-patterns
- Ask you to read `.ai-frame/` files at the start of each session

You can also instruct Claude at the start of any session:

> "Read `.ai-frame/progress.md`, `.ai-frame/decisions.md`, and the most recent file in `.ai-frame/sessions/` to get up to speed."

### 5. End a session

```bash
python /path/to/ai-frame/session_manager.py end --project-dir your-project
```

The script asks:
- What did you accomplish?
- Any architectural decisions made?
- What are the next tasks?
- Any blockers?

It saves a dated summary in `.ai-frame/sessions/YYYY-MM-DD.md`, and optionally updates `progress.md` with the next tasks and `decisions.md` with new decisions.

## Commands Reference

### `init_project.py`

```
python init_project.py [--project-dir PATH]
```

Runs the initialisation wizard. Safe to re-run — backs up any existing `CLAUDE.md` before overwriting.

---

### `session_manager.py`

```
python session_manager.py <command> [--project-dir PATH]
```

| Command  | Description |
|----------|-------------|
| `start`  | Print session briefing, create today's session file |
| `end`    | Record session summary, update progress and decisions |
| `status` | Print compact project status |
| `update` | Interactively append content to a context file |

---

### `context_builder.py`

```
python context_builder.py [--project-dir PATH] [--output FILE] [--compact] [--sections LIST]
```

Assembles all `.ai-frame/` files into a single context snapshot. Useful when:
- Starting a chat in a non-Claude Code interface (e.g. claude.ai)
- Checking how many tokens your context consumes
- Generating a context file to commit or share

| Flag | Description |
|------|-------------|
| `--output FILE` | Write to file instead of stdout |
| `--compact` | Strip placeholder comments and empty sections |
| `--sections a,b,c` | Include only listed sections: `config`, `progress`, `architecture`, `decisions`, `sessions` |

Example — build a compact context for a chat interface:

```bash
python context_builder.py --compact --sections progress,decisions,sessions --output context.md
```

## Recommended Workflow

```
Session start
─────────────────────────────────────────────────────────────
1. git pull / check branch
2. python session_manager.py start      ← see what's happening
3. Open project in Claude Code
4. Claude reads CLAUDE.md automatically
5. (Optional) Tell Claude: "Read .ai-frame/progress.md and recent sessions."

During session
─────────────────────────────────────────────────────────────
- Work normally in Claude Code
- When a significant decision is made, note it mentally or jot in decisions.md
- If plans change mid-session, update progress.md via `session_manager.py update`

Session end
─────────────────────────────────────────────────────────────
1. python session_manager.py end        ← record accomplishments and next tasks
2. Review and edit .ai-frame/progress.md if needed
3. git commit .ai-frame/ along with code changes
```

## Keeping Context Lean

The whole point is to reduce token usage. Here are practices to keep context files from bloating:

| File | How to keep it lean |
|------|---------------------|
| `progress.md` | Replace, don't append. Each session should have a current "Next Up" section, not a growing list. |
| `architecture.md` | Keep it high-level. Link to actual code files rather than copying code into the doc. |
| `decisions.md` | Archive old entries by moving them to `decisions_archive.md` once they're no longer actively relevant. |
| `sessions/` | Only the last 2–3 sessions matter. Archive or delete older ones. |
| `CLAUDE.md` | Avoid long prose. Bullet points are better. The file should rarely exceed 150 lines. |

Use `context_builder.py` with `--compact` to get a token estimate and see what's eating space:

```bash
python context_builder.py --compact 2>&1 | tail -1
# ~1,847 estimated tokens
```

## Editing `CLAUDE.md` Manually

The generated `CLAUDE.md` is a starting point. Edit it freely:

- Add new constraints discovered during development
- Refine the architecture principles as the system evolves
- Add file-path conventions, naming rules, or domain vocabulary
- Remove sections that don't apply

If the project phase changes (e.g. from `active_development` to `maintenance`), just edit the Phase line — no need to re-run the wizard.

## Multiple Projects

AI Frame supports any number of projects. Each project has its own `CLAUDE.md` and `.ai-frame/` directory. Use `--project-dir` to target any project from anywhere:

```bash
python ~/tools/ai-frame/session_manager.py start --project-dir ~/projects/my-api
python ~/tools/ai-frame/session_manager.py start --project-dir ~/projects/my-cli
```

## Tips

- **Commit `.ai-frame/`** to version control. It's project knowledge, not tooling.
- **`CLAUDE.md` is the highest-leverage file.** Spending 10 minutes refining it saves many multiples in every future session.
- **Session files are a searchable history.** Run `grep -r "decision" .ai-frame/sessions/` to find when something was decided.
- **For new team members**, the `.ai-frame/` directory gives them instant project context — point them there before their first session.
